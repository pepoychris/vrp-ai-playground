RoboRoute Nexus

Route intelligence for the last mile.

A 3D control tower that solves a vehicle routing problem with OR-Tools, draws the plan on a deterministic low-poly city, lets you close a road and re-plan, and explains every revision with a language model running on your own machine.

What it does

One city, one depot, a plan you can operate

Every surface is driven by the frozen REST/SSE contract: the same revision the solver produced is the revision the copilot reads.

  • Bounded optimisation

    OR-Tools solves the routing problem from the deployed fleet and the generated orders, then reports distance, drive time, delay, unassigned orders and the economic cost behind the revision.

  • Deterministic city

    63 nodes, 110 road edges, 48 blocks and 137 buildings generated from a versioned local dataset and drawn with Three.js in an isometric operational view.

  • Operable simulation

    Start, pause and change speed. The robots drive the plan while the clock advances, and the renderer reports real draw calls, triangles and frame rate.

  • Road closures

    Arm the closure tool and drag across a road to block it in both directions. The map paints it coral, lists the affected vehicles and orders, and re-plans.

  • Local AI copilot

    Install qwen3:4b on demand with streamed progress, activate it, ask about the revision on screen and get an answer that cites the fields it used.

  • Shift report

    Build a Markdown shift report from deterministic metrics plus an AI narrative, including the before/after comparison of the last intervention, then download it for sharing.

Quick start

Bring it up, then run a shift

Docker Desktop with Compose v2 and a browser are the only prerequisites. The first AI install also needs Internet access once, to download the model.

1. Start the stack

git clone https://github.com/pepoychris/vrp-ai-playground.git
cd vrp-ai-playground
docker compose up --build

Open http://localhost:8080. The API health endpoint is http://localhost:8000/health. The stack starts idle by design: API online, simulation stopped, model not installed, no scenario created.

2. See it working, click by click

  1. 01
    Start Optimizing

    Leaves the landing screen and opens the control deck with the empty city.

  2. 02
    Fleet → Deploy Fleet

    Choose the vehicle count (two robots is the shortest path) and deploy them.

  3. 03
    Generate Orders

    Six orders is enough to make the plan interesting; they appear on the map.

  4. 04
    Optimize Routes

    OR-Tools solves it and the glowing routes, KPIs and route table fill in.

  5. 05
    Start Simulation

    The robots drive the plan. Raise the speed to x4 to watch the clock move.

  6. 06
    Arm the closure tool, drag across a road

    The road turns coral, the panel lists affected vehicles and the scenario re-plans.

  7. 07
    Analytics → AI copilot

    Install Qwen Core if needed, activate it, ask a question and build the shift report.

3. Run it without Docker

Backend, from the repository root:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r api\requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn api.app.main:app --reload --port 8000

Frontend, from a second terminal:

cd frontend
npm ci
npm run dev

Vite serves the UI at http://localhost:5173 and proxies /health and /api to port 8000.

Architecture

Three containers, one published origin

The browser talks to one origin. The frontend proxies to the API, and only the API may reach the model runtime.

  1. Browser

    React + Three.js control deck

    Landing page, deck, 3D city, copilot panel. Same-origin HTTP and SSE only.

  2. edge network

    frontend :8080

    Serves the built bundle and proxies /api and /health.

  3. backend network

    api :8000

    Scenario state, road graph, OR-Tools solver, simulation clock, AI orchestration.

  4. backend network

    ollama (no published port)

    Fixed qwen3:4b runtime, cloud disabled, model stored in a volume.

One revision, one truth

  1. Command A mutation returns the new scenario revision.
  2. Event The same revision is streamed to the browser over SSE.
  3. Render The city, the KPIs and the tables read that revision.
  4. Explain The copilot receives the snapshot it is grounded on.
  5. Gate An AI proposal only mutates the scenario after confirmation.

Optimisation is bounded on purpose: OR_TOOLS_MAX_TIME_SECONDS caps solver wall-clock, and the cost model is deterministic so two identical shifts produce the same plan.

Local AI

Install on demand, activate, ask, report

The backend fixes the model name and the inference policy. The browser cannot select an arbitrary model and never talks to Ollama directly.

  1. 01

    Install Qwen Core

    Starts the on-demand pull and streams progress through /api/ai/model/install/events. Nothing is downloaded until the operator asks.

  2. 02

    Activate AI core

    Preloads qwen3:4b with the approved context and temperature settings; the panel shows when the core is loaded.

  3. 03

    Ask the copilot

    Sends the visible scenario snapshot plus the question. The answer is validated and tagged with the revision it used, together with any suggested action.

  4. 04

    Build and download the report

    Combines deterministic metrics with an AI narrative and exports the shift report as Markdown, including the A/B comparison against the previous plan.

What the model never does

  • It does not calculate distances or replace OR-Tools.
  • It does not apply an action without explicit confirmation.
  • It does not answer about a revision other than the one on screen.
  • It is never reachable from outside the Compose network.

  • Visual The Playwright suite records the screenshots used on this page.

Scope

What this is not

An offline-first demonstration of a last-mile control tower, not a production dispatch system.

  • No authentication or multi-user permissions.
  • No GPS, geocoding, live traffic or weather.
  • No mobile client and no RAG/vector store.
  • The city is a fictional dataset; fixture assets are procedural stand-ins.
  • The copilot explains and proposes; it never drives the solver.
